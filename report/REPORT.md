## 各手法が効いている様子 (図の読み方)

横軸はすべて**起動からの実時間 [s]**、各パネルのタイトルがそのまま結論。

- **A. GPSDO ロック (log)**: `|freq − ロック値|` を log-y で。起動時 ~2400ppb のズレが減衰=水晶ドリフトを
  学習。**赤縦線がロック時点 (8サンプル)**。ロック後の微振動は σ~数 ppb の実周波数揺れ + log の 0 交差
  スパイク (高精度ゆえの見た目)。水晶誤差そのものは +2.4ppm。
- **B. 時刻同期 ns 級**: GPSDO 補正後の UTC 予測残差。**MT3333 1PPS 仕様 ±10ns の帯 (緑) の内側**に
  収まる = ns 級の時刻同期。
- **C. PPS ジッタ分布**: 横=各平均からのズレ[ns]=**ジッタ量そのもの**、縦=該当パルス数 (頻度)。
  ①受信した GPS PPS、②自作の規律 PPS を grouped (横並び) で。**棒が数本しかないのは、値が 16ns 刻み
  (PIO 捕捉=2cyc@125MHz の分解能限界) でしか取れず、ジッタがその数段階 (±48ns) しか広がらない**
  = 量子化以下に安定、という意味。① ② が同程度=受信と同じ綺麗さで生成 (①は MT3333 仕様 ±10ns 相当)。
  さらに細かく見るには捕捉を 8ns 化 (PIO 2SM インターリーブ) が必要。
- **D. 位相同期の収束 (symlog, PIO測定+PID+Smith)**: 規律出力エッジの UTC 秒境界からのズレ。起動の
  ~2.4ms から引き込み **σ≈48ns (sub-µs) に貼付**。旧ソフト (Instant 測定) は ±~1.4ms 止まりだった → 測定の
  PIO ハード化(stage②) + Smith 予測子で遅延補償して達成 (詳細は下記 compare.png / smith.png)。

## stage ②: 位相測定を PIO ハード化 → 出力を UTC 秒に ns で同期

![compare](compare.png)

位相を Instant でなく **PIO の生カウンタ差**で測る (出力エッジ vs GPS PPS、両 SM が同じ clk_sys)。
旧(Instant 制御) と 新(PIO ハード制御) を同じ指標 (PIO 真値 `hwphase`) で比較:
- **A. 出力位相**: 詰める 3 段階を実データで重畳 — **① Instant 測定で制御 = ロック不能 (±190µs)** /
  **② PID (PIO 測定, Smith 無し) = ループ遅れで振動 (σ~300ns)** / **③ PID+Smith (遅延補償) = σ~35ns で
  UTC 秒に貼り付く**。測定(Instant→PIO)と制御(PID→PID+Smith)の両方が効いているのが見える
  (制御項の詳細は tune.png、Smith の before/after は smith.png)。
- **B. 測定精度**: 同じ出力を両方で測った差 = Instant の測定ノイズ **σ~360µs** (ウェイクアップ遅延) vs
  PIO **16ns** (~2万×)。この測定差が出力をどこまで締められるかを決める = stage ② の肝。

**弱信号での蹴り対策 (定石)**: 窓際は GPS PPS が ~19% 欠落/不正。①GPS 世代が進まないエッジは補正スキップ
(欠落ホールド)、②ロック中に 50µs 超の位相は単発 garbage として棄却 (外れ値除去)。これで ~100ms の蹴りが消える (罠 15)。

**定常オフセット → type-II PI**: P のみだと水晶の残差周波数誤差に対しドループ(実測 ~+550ns オフセット)。
位相を周波数トリムに積分する **I 項**を足すと残差を吸収し**オフセットが 0 に収束** (`trim_ppb` が ~−43ppb に
巻き上がり位相 +550ns→~0)。これで mean≈0・σ~300ns に。

`uv run webapp/plot_compare.py report/compare-old.log report/compare-new.log out.png` で再生成
(`PHASE_USE_HW=false` でビルドした Instant 制御版が旧、`true` が新)。

## 制御方式 (P / PI / PID) の比較とゲインチューニング

各構成を**別々の走行でコールドスタート(2.4ms)から**撮り起動エッジで重ねた公平比較 (`CTRL_SEL` でビルド,
`webapp/plot_ctrl.py`。巡回だと前構成の終状態を引き継ぎ初期条件が揃わないため):

![ctrl](ctrl.png)

全構成が 2.4ms から始まり、定常まで撮ると構造がはっきり出る:
- **P/PD = +370ns に**ドループ**(I 無し→オフセットが残る)**。PD σ30 < P σ55 (D がジッタを減衰)。
- **PI/PID = 0 中心 (I がオフセットを消す)** だが **Kp1/16 で振動** (σ~100ns, type-II underdamped)。
- **PID+Smith = 最速で σ~38ns に tight**。Kp1/8 は **Smith の遅延補償**で初めて安定 (1/8 だけだと PI は発散)
  = **Smith が高ゲイン=速い収束+減衰を可能にしている**。

下記はオフライン sim での定量比較 (同じ外乱で各構成を回す):

![tune](tune.png)

「PI だと残差振動がある。D は要る？」を検証。**実機ログから外乱(系統ドリフト+測定フロア)を取り出し、
任意ゲインのコントローラをオフラインで回す**(リフラッシュ不要)。firmware は `PHASE_EXPERIMENT=true` で
P→PI→PID を巡回し制御信号(cfg/trim/p_ns/d_ns)を全部ログ → `uv run webapp/tune_gains.py exp.log`。

- **左図 (各項の応答, 初期 2µs オフセットから)**:
  - **P のみ**: 残差周波数に対しドループ = **+470ns のオフセットで停まる**(σ120ns と静かだがゼロでない)。
  - **PI**: I 項が残差を吸収し**オフセット 0**。但し type-II + ループ遅れで**振動** (σ371ns)。
  - **PID**: **D 項(位相速度)が振動を減衰** (σ371→**249ns**)。完全には消えない = 遅延律速の本質的残り。
- **右図 (モデル検証)**: 実機 PID(σ286ns) と sim PID(σ249ns) の**滑らかさ・振幅が一致**。
- **掃引**: 推奨 **P=1/8, I=1/128, D=1/4**。但し実機 P=1/4 で発振歴があり sim を鵜呑みにできないので、
  **本番は保守的に P=1/16,I=1/128,D=1/4 (PID)** を採用。実機実測 σ~300ns・mean~0。

**外乱モデルの教訓 (重要)**: 当初 sim を**白色ガウス外乱**にしたら **実機より振動が過大**になった。実機の外乱は
隣接 16ns/edge と**滑らか(相関あり=水晶/GPS は白色でない)**。**AR1 相関ノイズ**に直すと sim が実機に一致した
(右図)。**閉ループからの外乱・プラント同定は本質的に難しく、sim は定性ツール (各項の役割・トレンド) と割り切り、
最終ゲインは実機で判断**。`PHASE_EXPERIMENT=true` で全制御信号をログ → `uv run webapp/tune_gains.py` で掃引。

**結論**: D は要る (振動を ~3 割減衰、実機でも PI σ347→PID σ300)。残差振動はループ遅れ由来。

## 精度をさらに詰める: Smith 予測子で σ 300ns → 35ns (smart-friend 分析 + 実機)

![smith](smith.png)

σ~300ns の支配律速を誤差二乗和で切り分けると: 測定量子化 16ns→σ≈4.6ns、GPS PPS ~10ns、RSS≈11ns
vs 観測 300ns → **測定+GPS 起因は分散の 0.13% だけ**。残り 99.9% は**制御のリミットサイクル**
(type-II の固有振動, 周期 ≈ 2π√Ki ≈ 71 エッジ = 実測と一致, ζ≈0.35)。→ **量子化 8ns 化や overclock は今は
無意味** (測定は誤差の 0.1%)。詰めるべきは制御。

単発の対策 (sigma-delta dither で actuator 8ppb 量子化除去・deadband=0・Ki=1/512 で ζ0.71) は**効かなかった**:
**ループ遅れ d≈2 が ζ 公式を裏切る**から。→ **Smith 予測子で遅延補償**: 在飛行中(前エッジに出した、まだ位相に
出てない) P/D 補正を引いた**予測位相 `pred=ctrl−last_pd`** で制御 → d が消え ζ 公式が成立。これで **Kp=1/8
(ζ≈0.71)** が本当に効き、trim が ±60ppb 振動から**滑らかに整定**、位相 ±50ns に。さらに弱信号スパイク(4-10µs)が
trim を蹴っていたので**外れ値棄却を 50µs→3µs に**。結果 **σ 300ns→35ns (~9×, mean~0, |max| 80ns)**、
測定フロア RSS≈11ns に肉薄。

**ここから先**: σ35ns は測定量子化が初めて効く域なので **8ns 捕捉化** (overclock/PIO 2SM) + holdover に
**TCXO** ($1-2)。**<15ns は GYSFFMANC+窓際アンテナの物理壁** (timing 受信機 u-blox LEA-M8T 等 + 良アンテナの
別プロジェクト)。採用済の改善: Smith 予測子 / 周波数 sub-8ppb 化 (sigma-delta) / 外れ値棄却 3µs。

## 達成のまとめ: 出力位相規律をオシロ無しで詰めきった

規律 PPS 出力の位相を、**オシロを制御に使わず (外部基準なし)** に詰めた。smart-friend (外部 AI) と原因を切り分けつつ
3 修正 + 2 頑健化を入れ、各段を実機・オシロ独立計測で検証:

| 指標 | 当初 | 最終 |
|---|---|---|
| ロック | しない (P only で停止) | **lk=1 安定** |
| ジッタ σ (オシロ N=120) | 216 ns | **35–46 ns** (設計 spec 35–48ns) |
| 出力 mean offset | −1.8 µs (制御アーティファクト) | **~+90 ns** (物理残差, sub-µs) |
| firmware `hwphase` ↔ オシロ | 3.7 µs 食い違い | **~160 ns 一致** |
| 短期安定度 (Allan, 自己計測) | — | ADEV@1s ≈ 1.3e-8 → 128s で ~1e-9 |

- **3 修正** (`e093f91`/`a1e980a`/`b8a2a16`): ① I 項を lock 窓から分離 (`i_enable_ns`) → 「lock しないと I が効かない / I が
  効かないと lock しない」鶏卵を解消、② K 較正前に FIFO drain → boot ごとの ~µs バイアス除去 (`PHASE_K verify=0`)、
  ③ runtime ペアリングの同秒保証 → ±3.26µs (=ppm×1s) スパイク除去。
- **頑健化** (`69fc093`/`97d0ab5`): reject/invalid 時の PLL 履歴汚染 (D の一発キック) 防止 / K 較正の diff 一致検査 + retry。
- **検証**: オシロ独立計測 (offset・σ・収束)、Allan 偏差の自己計測、ロック収束を**自己申告 + オシロの 2 系統で一致**確認。
- **床**: 残り ~90ns の絶対 offset は受信機 PPS + アンテナケーブル + pad の物理オフセットで、**外部基準なしには分離不能**
  = この構成の限界。さらに詰めるなら `qErr` を出すタイミング受信機 (後述「さらに詰めるには」)。

以下に詳細・全図 (before/after・分布・Allan・収束)。

## オシロで出力位相を独立検証 (Rigol DHO800)

firmware の自己申告 (GP3→GP4 ループバック) とは別に、**ピンの生信号をオシロで直接**測って出力位相を裏取りした。
CH1(黄)=GPS 受信機 1PPS を**横軸中央=0** に置き (基準・トリガ)、CH2(青)=GP3 の規律 1PPS との立ち上がり差を見る
([`scope_pps.py`](scope_pps.py)、依存ゼロ・SCPI over LAN)。

### なぜ位相まで規律するか (`hwphase`→0 の目的)

GPSDO は周波数と位相の 2 段。**周波数**だけ合わせると出力は正しいレートで回るが、エッジは 1 秒の任意位置に居る
(起動時の位相のまま) し、ppb 推定の僅かな誤差で位相が**ゆっくり walk** する。**位相ループ (`hwphase`→0)** は出力エッジを
**GPS = UTC 秒境界に貼り付ける**もので、これで初めて出力が「周波数標準」でなく**時刻標準 (エッジ = UTC 秒)** になる
(type-II の積分項が長期位相を固定)。`0` = 出力エッジ = GPS エッジ、の自然な目標。

### 出力位相: GPS より ~2µs 早い (リード) と、そのばらつき

GP3 の立ち上がりは GPS PPS より **~2µs 早い (リード)**。これは「GPS エッジを見てから出す」遅延線ではなく、
**規律された自走発振器**でサーボがエッジを 1 秒のどこにでも置けるため (リードもラグも可)。差は固定オフセットだが、
時間とともに ~1.4〜2.2µs を緩慢にふらつく — 差が小さいとき / 大きいとき:

![small offset](scope-pps-small.png)
![large offset](scope-pps-large.png)

*左=差小 (≈1.36µs)、右=差大 (≈2.18µs)。0.6V/div・1µs/div。0V を下端寄りにして 0–3.3V を画面いっぱいに。*

N=120 ショットの分布と時系列:

![phase distribution](scope-phase.png)

```
GPS->gen phase:  mean = -1788 ns   sigma = 216 ns   pp = 899 ns   (N=120)
```

- **mean ≈ −1.8µs (負=リード/早い)** は固定オフセット。サーボは loopback 位相 (GP3→GP4 を GPS と同じ PIO
  カウンタで捕捉した `hwphase`) を 0 に駆動する設計で、K はブート時に**両 SM で同じ GPS エッジ (GP2)** を捕って
  較正した純カウンタ間オフセット。残る ~1.8µs は出力エッジ生成 vs 捕捉の定常残差で、**σ には効かず**符号(リード)は偶発。
- **σ ≈ 216ns** はばらつき。GPS PPS の sawtooth に加え、サーボの**緩慢な位相 wander** (時系列が ~1.4〜2.2µs を往復) を
  含む。長基線で測るほど wander が乗って大きく出る (エッジ毎の短期ジッタはこれより小さい)。

### 固定オフセットを詰める (オシロ不要)

firmware は GP3→GP4 ループバックで**自分の出力位相を自己計測**している (`hwphase`)。これが真値なので
**オシロ無しで詰められる**: サーボの位相ターゲットに固定バイアスを与えて `hwphase` を狙い値へ寄せる、または定常残差の
原因 (loop の deadband / ゲイン / Smith 項) を詰めて 0 収束させる。オシロが要るのは (a) ループバックのバグ検出の独立確認、
(b) GPS モジュール自身の PPS-vs-UTC オフセット (数十ns・spec) やアンテナケーブル遅延の**絶対**校正 — これらは外部時刻
基準が要り firmware だけでは取れない (が ~1.8µs とは別物)。

### 定常残差は制御で詰まるか

詰まる。loop は **type-II** (Smith 予測位相を freq trim に積分; [`gnssdo` PLL](../gnssdo/src/pll.rs) の I 項は
コメント通り「定常オフセットを 0 へ駆動」) なので、**定常位相誤差は本来 0 に積分されるべき**もの。~1.8µs が残るのは
積分が効ききっていない兆候で、原因候補:

1. **積分の gating**: `trim` は `valid && locked` の時だけ積分する。窓際の限界 fix で valid 位相が疎だと積分が停滞し、
   エッジが wander する (実測の ±0.4µs ふらつきと一致)。
2. **外れ値棄却** (`outlier_ns`=3µs): post-lock で `|phase|>3µs` を hold。荒れた fix だとサンプルを間引いて積分を飢えさせる
   (残差 1.8µs はこの閾値に近い)。
3. **測定バイアス**: `c0` (GPS, pps_task) と `x` (出力, gen_capture_task) を別タスクで対にする際の固定スキューは
   ループの「センサ自身の偏り」で、ループ利得では消せない (測定/ペアリング側の修正が要る)。
4. **意図的に遅い積分** (`i_den`=128 ≈ 71s): 1-sample 遅れの限界周期 (`λ²−λ+k`) に対する安定性確保。Smith 予測子は
   この遅れを補償して利得を上げるためのもの — 利得を闇雲に上げると発振する (本レポート前段の格闘点)。

**実機で検証 (smart-friend と切り分け)**: 原因は **(1) の lock gating** だった。`locked` は `|ctrl| < lock_ns`(1µs)で、
I はロック中のみ積分する。残差 1.8µs は 1µs 窓の外なので**永久にロックできず I が立ち上がらない鶏卵**になり、
P only として残留周波数誤差と P 補正が釣り合う非ゼロ位相で停止していた。対策は **I 有効化窓を lock 窓から分離**:
[`gnssdo` PLL](../gnssdo/src/pll.rs) に `i_enable_ns`(既定 ±5µs)を足し、I を `|ctrl| < i_enable_ns` で積分(ゲインは不変)。
これで P が 1µs 窓に入れなくても I が帯内で engage しロックまで引き込む。

実機結果 (オシロ独立計測):

| | 修正前 | 修正後 |
|---|---|---|
| ロック | しない (P only) | **lk=1** |
| ジッタ σ | 216 ns | **34 ns** (≈6×, 設計 spec σ35–48ns に一致) |
| 積分 trim | 0 | 非ゼロ (engage) |

制御は設計どおり機能するようになった。**ただし絶対 mean は (3) の K 較正バイアスが支配的に**: 修正後、firmware の
loopback `hwphase ≈ −0.3µs` に対しオシロは `−4µs` で **~3.7µs 食い違う** (前 boot は両者一致)。loopback の「0」が
boot ごとの K 較正でズレ、ループはそれを忠実に追うだけ (ループ利得では消せない sensor バイアス)。mean を詰めるには
K 較正の頑健化 (良 fix / 外れ値除去 / サンプル増) か一度きりの feedforward 較正が要る — 制御でなく**測定側の課題**。

**K 較正の頑健化 (実装・検証, smart-friend と切り分け)**: 原因は **boot 時の K サンプルが別エッジ同士をペア**に
していたこと。`c0`(SM0)/`c2`(SM2)の RX FIFO に古い値が残ると 1 エッジずれ、loopback の fold は公称秒なので K に
「実秒ぶんの tick」が混じり mean が **水晶 ppm × 1s ≈ 数µs** だけ boot ごとにズレる (観測 3.7µs ≈ 3.7ppm)。対策:
**K 較正前に両 SM の FIFO を drain** し同一エッジを捕る ([main.rs](../pico-gnss/src/main.rs))。実機: `PHASE_K diff` が
6 サンプル全て一定、SM2 を GP2 のままの **`PHASE_K verify phase_ns=0`** で K 正当性を確認。mean は −4µs → **−0.9µs** に
改善し、firmware と オシロが数百 ns まで一致。

**runtime のペアリング (実装・検証)**: 同じ 1 エッジずれが**運用時の位相計測**でも起きていた。出力は GPS より僅かに
先行するので、`gen_capture` が出力エッジ `x[N]` で起きた時点ではまだ `pps_task` が `GPS[N]` を store しておらず、
`C0_GPS` は `GPS[N-1]` のまま → `x[N]` を `GPS[N-1]` と対にして **+3.26µs (ppm×1s) のスパイク**。レースなので intermittent
で、`hwphase` が ~−0.8µs と ~+2.3µs の二峰になりロックを外し σ を 216ns に戻していた (先の σ=34ns は spike を拾わなかった
静かな窓)。対策: `x` 直後に**同秒の GPS エッジ (世代 `C0_GEN` の進行) を短時間だけ協調待ち** (`yield_now`、busy wait 不可:
`pps_task` と同 executor / `C0_GEN` は Release・読み手は Acquire / GPS 先行・欠落時は timeout し既存 gating でホールド)。

**3 つの修正の最終結果 (オシロ独立計測, N=40)**:

| | 当初 | 最終 |
|---|---|---|
| mean オフセット | −1.8 µs | **+0.11 µs** (~16×) |
| ジッタ σ | 216 ns | **35 ns** (≈6×, 設計 spec 35–48ns) |
| ロック | しない | **lk=1 安定** |
| firmware `hwphase` ↔ オシロ | — | ~160ns まで一致 |

`hwphase` は ±100ns 内に収束しスパイク消失。残る ~110ns の mean は loopback 経路 + ケーブル + 受信機 PPS 固有の
物理オフセットで、絶対 UTC 整合が要るならここを一度ケーブル較正で焼けばよい (制御ではこれ以上は受信品質律速)。

![GPS と整合した出力 1PPS](scope-pps-aligned.png)

*3 修正後 (**100ns/div** に拡大 — オフセットの桁が µs→sub-µs に変わったため)。CH1(黄)=GPS を中央=0、
CH2(青)=GP3 の立ち上がりが**ほぼ重なる** = offset が **当初 ~2µs リード → ~90ns** に。mean +90〜100ns / σ ~50ns
(sub-µs を wander; 単発フレームは数十〜200ns とばらつく)。当初の ~2µs リード ([scope-pps-small.png](scope-pps-small.png)
は 1µs/div) とは桁違い。**この ~90ns が物理残差の床**(受信機 PPS + ケーブル + pad; 外部基準なしには分離不能)。*

**オシロ外部観測**の両方で計測 ([`plot_converge.py`](plot_converge.py)):

![ロック収束](convergence.png)

- **左 (自己申告, symlog)**: 起動直後 ~100µs から急降下 → 負へオーバーシュート (~-1µs) → 0 へ整定。
- **右 (オシロ外部)**: 窓 (±5µs) に入った時点 (~4µs) から同じ形 — 0 を切ってオーバーシュート → 減衰リップルで整定。

2 系統が**同じ収束形 (オーバーシュート + 減衰)** を独立に示す = type-II ループのステップ応答 (ζ≈0.7) が外からも裏付け
られた。オシロは窓に入る前の広域 (~100µs〜) は見えない (self-report が担当) が、最終引き込みは ns で一致。

### ループバック無しの構成では

ループバック (GP3→GP4) は出力エッジ vs GPS を ns でハード測定して**位相を閉ループ化**する仕組み。外すと:

- **周波数 / holdover はそのまま効く** — ppb は GPS PPS 間隔だけで測り、出力を見ないため。
- **位相は閉ループが使えない** → **フィードフォワード (開ループ)** に倒す: GPS timestamp + 定数〔GPS 捕捉 SM と
  出力 SM のカウンタ間オフセット + 出力生成の確定レイテンシ〕で出力エッジを目標位相へ置く。PIO はサイクル確定的なので
  この定数は計算 or 一度だけ較正して焼ける (適用にオシロ不要)。弱点は**自己検証 / 補正が無い**こと (HW 確定なので実害は小)。

要はループバックは「ピン 1 本 + 配線で**測って自動補正** (未モデルの定数も吸収)」を買うもの。無くすなら
「**HW のサイクル確定性を信じて定数を焼く**」に倒すトレードオフ。MCU でピンが惜しい構成では後者が定石。

### 出力パルス幅 (撒き直し用 1PPS)

GP3 は規律済み 1PPS の**撒き直し**。規律対象は立ち上がりエッジなので幅は自由 — 外部機器へ配れるよう
**100ms** にした (u-blox / 一般 GPS モジュールの標準幅, NMEA も同様)。PIO に high 用カウントダウンを 1 本足し、
high 幅を起動時に 1 ワード push して保持。幅は low 周期から差し引くので**立ち上がり時刻は不変** (位相 σ に影響なし)。
幅は [`output_high_cycles`](../rp-pps/) で µs〜100ms 任意に設定可能 (カウンタ/scope 用途なら数 µs)。

![GP3 100ms 1PPS](scope-pps-100ms.png)

*20ms/div。CH2(青)=GP3 が立ち上がり後 100ms high (実測 `PWIDth`=99.999ms)、その後 low。規律はロック維持
(`PPSGEN interval≈1.000000s`)。*

落とし穴 (DHO804): SCPI エラーキューは FIFO なので**全部 drain してから**判断する / `:MEASure:CLEar` は引数なし
(`ALL` で `-108`) / GPS PPS は ~100ms の広パルスなので µs 窓の delay/period 自動測定はエッジを対にできず波形ダンプで差分。

## さらに詰めるには: どんな GNSS 受信機なら

σ も絶対オフセットも、いまの床は **受信機 (AE-GNSS-EXTANT = GYSFFMANC / MediaTek MT3333, 民生ナビ向け)** で
決まっている。**タイミンググレード受信機**の以下の機能があれば、(オシロのような外部基準なしでも) さらに詰まる:

1. **sawtooth (量子化誤差) の報告 `qErr`**: u-blox M8T/M9T・ZED-F9T 等は PPS の量子化誤差をパルス毎に ps 単位で
   出力する。引き算すれば **±数十ns の sawtooth が消えて σ が縮む**。MT3333 は出さない → 今の σ 床の一部。
2. **タイミング用 PPS 精度 + アンテナケーブル遅延補正**: PPS-vs-UTC を **±数ns** で規定 (民生は ±数十ns)、かつ
   **アンテナケーブル遅延を設定**できる → PPS ピンが真 UTC に補正される。これは「内部から観測不能」とした
   **絶対オフセットの一部 (受信機 PPS + ケーブル分) を受信機側で潰せる** = 床が下がる。
3. **survey-in / 固定位置 (定点タイミングモード)**: 位置を長時間平均 or 既知固定にして測位解を大幅改善し、
   **位置誤差が時刻へ漏れ込むのを抑える**。民生ナビモードは位置ノイズ律速。
4. **多バンド / RTK**: 良アンテナ + 開けた空で位置 sub-ns 級 → 時刻も向上。
5. (受信機外) holdover 用に **TCXO/OCXO** を GPSDO 側へ。PPS 断時の時刻保持が桁違いに。

要は **`qErr` を出し・ケーブル遅延補正と定点モードを持つタイミング受信機** (例: u-blox ZED-F9T) に替えれば、
(a) sawtooth 補正で σ、(b) ケーブル遅延補正で絶対オフセットの一部、(c) 定点モードで位置由来ジッタ、をいずれも
下げられる。現状は MT3333 が σ・絶対値の両面でこのプロジェクトの律速。

## 最適化実験: loop TC と「自己計測の限界」

Allan(自己計測)を手がかりに、smart-friend と相談しつつ **loop TC を伸ばす**実験をした
(`i_den` 128→512, `d_den` 4→16 = 時定数を伸ばし D を弱める)。狙いは GPS PPS ノイズをもっと平均化して出力を綺麗に。
実機(各 N=100, 窓際 fix):

| | baseline (i_den=128, d_den=4) | tuned (i_den=512, d_den=16) |
|---|---|---|
| offset mean | 230 ns | −5 ns |
| σ (オシロ, vs GPS) | 70 ns | **110 ns** |

**結論: 閉ループ σ では loop 最適化を判定できない(交絡)**。TC を伸ばすと出力は真 UTC に近く滑らかになるが、基準の
GPS PPS 自体がノイジーなので **σ(出力 vs GPS)は GPS ノイズ床へ向かって増える**。実際 σ は 70→110ns に「悪化」したが
これは tuning が悪いのではなく交絡(smart-friend の予言どおり)。mean 差(230→−5ns)は reception wander で tuning 由来でない。

**正しい判定法(self-measure)**: ロック→**holdover を H 秒(10〜600s)振り、終端位相誤差 vs H** を見る。GPS ノイズ平均化の
利得は短中期 H で、水晶ドリフトの損は長期 H で出る → その交点が最適 TC。ただし数十回×長時間が要り本セッションでは未実施。
**しかも素水晶(TCXO なし)では交点 τ が短く、loop tuning の伸びしろは小さい** — 本当の利得は TCXO + qErr 受信機。

→ production 既定 (`i_den`=128, σ≈35ns 実測) を維持。**収穫**: 外部基準なしの loop 最適化は閉ループ σ では測れず、
holdover-endpoint 法が要る/かつ HW(水晶・受信機)律速、と実機で確認した。

## 設計の核と教訓

1. **PIO ハードキャプチャ**: PPS を CPU 割込でなく PIO 自走カウンタで時刻印字 → M0+ の critical-section
   マスクに依存せず σ ~10ns (ソフトの ~9µs 下限を突破)。
2. **GPSDO**: PIO の精密 PPS 間隔で水晶 ppb を EMA 推定 → 時刻を規律。PPS 断中も周波数外挿 (holdover)。
3. **時刻補正の ns 化**: エポックも予測も PIO の ns 時刻にし、Instant の µs アンカーを回避 → err σ ~10ns。
4. **規律 PPS 出力**: SM1 が周期をハード生成、SM2 が GP3→GP4 ループバックで ns 計測。周波数=16ns。
5. **位相同期の限界 (重要な教訓)**: 制御対象 (周期) の精度 (ns) と、フィードバックの「測定」精度 (ms) は
   別物。位相を CPU の Instant で測ると executor のウェイクアップ遅延が乗り ms で頭打ち。**ns 位相同期は測定を
   ハード化 (PIO で出力エッジを GPS PPS と同じカウンタで捕捉) する stage ② が唯一の道**、と実測で確定。
   - 制御ループ自体の教訓: 1 サンプル遅れに連続比例制御をかけると `λ²−λ+k=0`。k=1 発振 / k=½ リンギング
     (周期8ステップ、実測と一致) / **k=¼ 臨界減衰**。詳細は [../NOTES.md](../NOTES.md) 罠12。
